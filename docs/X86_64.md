# AquaOS x86-64

AquaOS supports only a native x86-64 kernel and LP64 userspace.
Run `sh qemu.sh` to build and boot it.

## Build and boot

On an x86-64 Linux host, install GCC/binutils, GRUB's PC boot tools, xorriso,
QEMU, and e2fsprogs. The build uses GCC in freestanding mode with host system
headers disabled and does not link Linux libc. Set `ZENOS64_CC` and
`ZENOS64_AR` to use an x86-64 ELF cross toolchain instead.

```sh
python3 tools/build64.py
python3 ports/tinycc/build.py --arch x86_64
python3 tools/iso64.py
python3 tools/disk64.py disk/zenos64-dev.img
qemu-system-x86_64 -m 128M -cdrom build/x86_64/myos.iso \
  -drive file=disk/zenos64-dev.img,format=raw,if=ide
```

The disk creation command refuses to overwrite an existing image. Reuse the
last QEMU command to retain guest files. After rebuilding userspace, create a
new image with a different name to install the new binaries.

For a fresh development environment, `sh qemu64.sh` builds everything and
creates a new disk under `disk/zenos64.XXXXXX/dev.img`. It prints that path and
retains the image after QEMU exits. Previous images are not overwritten.

Outputs live in `build/x86_64`: `myos.kernel`, `myos.iso`, `libc.a`, user
executables in `user/`, and the compiler installation tree in `root/`.
Root-level `build.sh`, `iso.sh`, and `make` use this build.
The kernel rejects ELF32 binaries.

## Architecture and ABI

* GRUB Multiboot v1 enters a small 32-bit bootstrap. It checks long-mode/SSE2
  support, builds bootstrap mappings, enables PAE and EFER.LME, and enters
  64-bit code. The temporary identity mapping is removed before kernel C code.
* The kernel uses four-level page tables. A dedicated supervisor-only 64 GiB physical window is mapped at
  `0xffff800000000000`, using 2 MiB pages. The kernel keeps its linked alias at
  `0xffffffff80000000`; the kernel heap starts at
  `0xffffffffc0000000`. Kernel mappings are supervisor-only and shared between
  processes. Fork clones user pages, and exit releases the cloned hierarchy.
* The GDT, 16-byte IDT gates, 64-bit TSS, ring transitions, interrupt frames,
  and timer-driven process switching use 64-bit state. Double faults have a
  separate IST stack. Kernel C code uses general registers only and disables
  the red zone. Process kernel stacks are 16 KiB.
* The C ABI is System V AMD64: 64-bit pointers and `long`, 32-bit `int`, and
  16-byte stack/allocator alignment. `long double` occupies 16 bytes and uses
  the x87 extended representation. x87 and SSE state is preserved per process.
* System calls retain the AquaOS numbers and `int $0x80` instruction, with
  native-width RAX results and RBX/RCX/RDX arguments. This is a AquaOS ABI,
  **not** the Linux syscall ABI.
* Initial user stacks contain native-width argc, argv pointers, NULL, environment pointers, and NULL.
  `crt0` passes argc/argv in RDI/RSI. The stack ends at `0x00007fffffffe000`,
  with 256 KiB mapped and an unmapped guard page. User pointers are checked
  against the canonical lower half and page permissions without truncation.
* The ELF loader accepts statically linked little-endian x86-64 ET_EXEC
  images, including virtual addresses above 4 GiB. It validates segment
  arithmetic, file bounds, executable entry points, and stack separation.
  Dynamic loaders, shared libraries, and ELF32 compatibility are not enabled.
* TinyCC targets x86-64 and installs as `/usr/bin/tcc`. Its runtime includes
  the x86-64 alloca and varargs helpers. The pinned linker is patched to resolve
  static PLT32 calls to defined symbols directly when linking GCC-built libc,
  and to fill static GOT entries before discarding relocation sections.

## Current limits

Physical allocation now uses usable Multiboot memory-map ranges below 64 GiB,
including RAM above 1 GiB and above 4 GiB. PMM allocation/free, VMM translation,
heap/stack backing and E1000 ring/buffer addresses retain all 64 bits. The NIC's
ring base registers program both low and high halves. Each process shares both
the dedicated direct-map hierarchy and the kernel's original linked hierarchy.
The fixed bitmap occupies 2 MiB, and bootstrap direct-map page directories
occupy 256 KiB. RAM at physical addresses 64 GiB and above remains unmanaged;
this implementation does not cover arbitrary machine sizes or memory hotplug.
Virtual addresses and user syscall pointers are 64-bit.

File offsets and stdio positioning are now signed 64-bit. Ext2 regular files
support direct, single-, double- and triple-indirect block trees and sparse
files above 4 GiB. Ext2 block-tree/sector-count limits and the ATA device
addressing limits remain; see [large files](LARGE_FILES.md).
User ELF pages currently retain the previous writable/executable mapping policy;
per-segment W^X/NX enforcement is a separate memory-protection improvement.
There is no 32-bit compatibility layer, Linux binary compatibility, SMP, or AVX
context management in this migration.

## Validation

```sh
python3 tests/shell_smoke.py --arch x86_64 --block-size 4096 --tinycc
python3 tests/shell_smoke.py --arch x86_64 --block-size 4096 --selfhost
```

The runner uses a disposable image and never changes development disks.
`--selfhost` rebuilds TinyCC twice inside AquaOS, runs generated programs, and
compares both compiler binaries. `--compiler-only --tinycc` runs a short native
compiler check; `--layout-only` selects the shorter shell/layout checks.

`abi64check` tests high stack pointers, invalid/noncanonical syscall pointers,
16-byte malloc alignment, extended registers, setjmp/longjmp, execution of an
ELF64 image above 4 GiB, and rejection of a wrapping ELF segment. The full suite
also checks pipes, Ctrl+C, fork/exec/wait, allocation failure rollback, user fault
isolation, stdio/varargs/floating point, editing, file mutations, and offline
ext2 integrity. Set `ZENOS_SMOKE_DISK=/tmp/debug.img` to retain the disposable
image for debugging after the runner exits.

## High physical memory validation

```sh
python3 tests/high_memory.py
```

The test builds with `PMM_HIGH_TEST`, boots QEMU with 5 GiB and starts allocation
at physical 4 GiB. It checks that the shell's page-table root is above 4 GiB,
runs repeated fork/write/free cycles over a 2 MiB buffer, and verifies ARP and
ICMP captures with E1000 DMA rings and packet buffers in high RAM. All three PCI
layouts and boot without a NIC are covered. The script rebuilds the normal
kernel and ISO afterward; run it with other builds stopped. It uses disposable
disks and leaves development disks unchanged. The 128 MiB network suite checks
normal low-memory operation separately. Machines between 5 GiB and the 64 GiB
physical ceiling have not been exercised by this QEMU test.
